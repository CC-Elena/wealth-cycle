### **1. 财务管理深化 (Phase 2 剩余核心功能) - 当前优先级最高**

- **M4-A Agent 智能化增强 (进行中)**
    - **LLM 基础设施**: 后端 `.env` 尚未配置真实的 LLM API Key，导致意图识别功能不可用。
    - **意图识别闭环**: 需要调通“自然语言录入 -> LLM 解析 -> 前端提议卡片 -> 用户确认入库”的完整链路。
    - **智能诊断 (M4-A2)**: 实现生存天数估算（Health Narrator），根据历史支出预测当前余额能支撑多久。
    - **主动管理 (M4-A3/A4)**: 识别异常大额支出、预算调剂建议、以及针对大额预判的“冷静期谈判”。
- **M5 固定账单管理 (前端缺失)**
    - **配置页面**: 目前后端 API 已支持固定账单（房租、水电等），但前端缺少增删改查的主页面。
    - **逻辑联动**: 发薪日自动预扣这些固定账单的逻辑需在前端引导中体现。
- **M6 储蓄与应急金管理**
    - **储蓄账户**: 显式的储蓄金额展示与管理。
    - **应急资金池**: 支持结余自动/手动转入应急金，并对动用应急金的行为进行原因强制记录。
- **M8 详细报表与历史趋势**
    - **详情页**: 提供比首页更细致的流水查询，支持按月、按分类的趋势图表。
    - **周期对比**: 本月 vs 上月、本发薪周期 vs 上一发薪周期的收支对比。

### **2. 物资与消耗管理 (Phase 3) - 闭环关键点**

- **M9 库存系统 (Inventory System)**
    - **入库联动**: 记账时勾选“入库”，自动将商品信息（规格、单价、保质期）写入库存批次。
    - **出库/消耗**: 手动标记消耗，或根据保质期提醒进行处理。
    - **浪费清单 (Waste List)**: 记录所有过期或利用率极低的物品，作为未来消费决策的负反馈。
- **M2 子项目拆分 (Split Transactions)**
    - **订单级录入**: 一笔 500 元的超市订单，支持拆分为具体的“生鲜、厨具、纸巾”等子项，并分别归类和入库。
    - **价格采集**: 形成商品的单价历史曲线，支持 AI 比价建议。

### **3. 消费控制决策 (Phase 4) - AI 核心价值**

- **M10 预购评估与冲动拦截 (Wishlist)**
    - **冷静期模式**: 锁定一笔钱进入“冻结状态”，到期后 AI 询问是否仍需购买。
    - **智能评分**: 根据当前资金状况、同类库存、历史浪费率对预购项进行系统打分（0-100）。
    - **决策记录**: 追踪有多少冲动消费在预购阶段被成功拦截。
- **耐用品回访任务**
    - **满意度追踪**: 对购买过的电子产品等耐用品，定期询问使用频率，回填“浪费/价值”评估。

### **4. 系统支撑与工程化完善 (S3)**

- **通知系统**:
    - 预算超支弹窗/推送。
    - 库存保质期预警。
    - 发薪日强提醒。
- **UI/UX 连贯性**:
    - 统一所有子页面的 `shadcn/ui` 风格。
    - 完善移动端适配（虽然目前是 Web 开发，但定位是 H5)。
- **安全性与隐私 (PRD 核心策略)**:
    - **数据导出**: 用户需能一键导出本地 SQLite 的所有流水。
    - **同步策略**: 虽然优先本地存储，但需要实现脱敏后的云端备份/同步功能。

### **总结建议**

后续开发应优先完成 **M4-A (LLM 连通)** 和 **M5 (固定账单管理页面)**，这两个功能能让现有的财务闭环从“纯记账”转变为“自动规划”；随后应切入 **M9 (库存系统)**，实现记账与实物的联动。
