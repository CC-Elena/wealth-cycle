# Proposal: 自动化调剂实验 (Automated Adjustment Experiment)

## Intent (原因意图)
目前系统的预算管理是静态的。用户设置每个月的预算块后，如果月中发现某个分类（如“饮食”）即将超支，而另一个分类（如“日用”）有大量盈余，用户需要手动调整。这种滞后性会降低用户的财务安全感。
本实验旨在引入 **“主动调剂”** 机制，利用 Agent 分析过去的消费速率预测月终结果，并提前提议将冗余资金调配至高风险分类。

## Scope (影响边界)
- **后端 (Sync & Agent)**:
    - 增加 `prediction` 算法逻辑：基于历史消费频率预测当前周期末的支出。
    - 扩展 `FluidBudgeter` 逻辑：生成调剂提议（Proposals）。
- **前端 (Dashboard & Agent UI)**:
    - 展示“预测超支”预警。
    - 展示 Agent 的调剂提议并支持一键执行。
- **数据模型**: 记录调剂日志，确保资金流向可回溯。

## Approach (方案方向)
1.  **消费轨迹预测**: 根据当前天数/周期总天数，结合已消费金额，计算线性预测值，并引入前三月同周期波动加权。
2.  **冗余判定**: 定义“安全水位”（如预测支出 < 预算 70%）。
3.  **主动提议**: 当 A 分类预测超支且 B 分类存在安全盈溢时，Agent 发起 `transfer_budget` 提议。
4.  **用户闭环**: 用户确认后，通过 `SyncShell` 异步更新预算块。

## Influence (财务环节影响)
- **对预算的影响**: 预算块的 `totalAmount` 会发生内部流转，但不改变周期总可支配资金。
- **对储蓄的影响**: 如果所有分类均有盈余，Agent 提议将总盈余的一部分提前划转至“储蓄”或“应急金”。
